## 📋 Quick Reference: File Organization Map

### Documentation Goes to `Document/` folder

| File Type | Destination | Notes |
|-----------|-------------|-------|
| **Deployment Guides** | `Document/Deployment/` | GCP setup, deployment scripts, automation docs |
| **Architecture Docs** | `Document/Architecture/` | System design, database schema, data flow |
| **Getting Started** | `Document/Getting-Started/` | Quick start guides, README, setup instructions |
| **ML/AI Docs** | `Document/ML-Pipeline/` | ML models, training data, pipelines, algorithms |
| **API Documentation** | `Document/API/` | API specs, endpoint documentation, integration guides |
| **Security Docs** | `Document/Security/` | Security policies, incident reports, compliance docs |
| **Progress/Status** | `Document/Progress/` | Status reports, timelines, checklists, milestones |

### Development Code Goes to `docs/` folder

The `docs/` folder is reserved for:
- API implementation details (in `docs/api/`)
- Architecture patterns & code organization (in `docs/architecture/`)
- Development-time documentation that's tightly coupled with code
- CI/CD pipeline documentation

## 🔧 Agent Instructions for File Generation

### When Creating New Documentation Files:

1. **Identify the Document Type**
   - Is it deployment-related? → `Document/Deployment/`
   - Is it about system design? → `Document/Architecture/`
   - Is it a quick start guide? → `Document/Getting-Started/`
   - Is it about ML/AI? → `Document/ML-Pipeline/`
   - Is it an API reference? → `Document/API/`
   - Is it about security? → `Document/Security/`
   - Is it a progress update? → `Document/Progress/`

2. **Check for Existing Files**
   - Before creating a new file, check if one already exists in the target folder
   - Update existing documentation instead of creating duplicates

3. **Use Consistent Naming**
   - Use clear, descriptive names
   - For progress files: `YYYY-MM-DD_PROGRESS_[TYPE].md`
   - Use UPPER_CASE with underscores for markdown files

4. **Include Metadata**
   - Add timestamp (for progress files)
   - Add version number (for guides)
   - Add update date
   - Include brief description at the top

5. **Cross-Reference**
   - Link to related documents in the same folder
   - Link to relevant code files
   - Include table of contents for longer documents

6. **Save Path Template**
   ```
   Document/[Category]/[YYYY-MM-DD_]FILENAME.md
   ```

### Never Save Documentation To:
- ❌ Root directory (except for critical project files like README.md for the project root)
- ❌ Random code folders
- ❌ `docs/` folder (unless it's code-related development documentation)

## 🚀 Implementation Guidelines

### For Agents in Any Mode:
1. Always refer to this file when deciding where to save documentation
2. If unsure about categorization, ask clarifying questions
3. Never mix documentation types in the same file (except high-level overview documents)
4. Use the Document/ folder structure as the source of truth
5. Keep docs/ folder for development-time code documentation only

### For Code Changes:
- Code changes go in their respective directories (backend/, frontend/, data-science/, cloud/)
- Related documentation updates should go to Document/ folder
- Never put development docs in root directory

### For Deployment:
- All deployment scripts stay in root or deployment-automation.ps1
- Deployment documentation goes to Document/Deployment/
- Configuration files stay in their respective folders (cloud/, backend/, frontend/)

## ❓ FAQ

**Q: Where should I save a file that covers multiple topics?**  
A: Save in the most primary category. Include cross-references to related documentation in other folders.

**Q: Should I update docs/ folder with deployment info?**  
A: No. docs/ is for development-time code documentation. Use Document/Deployment/ for all deployment guides.

**Q: How often should I create progress files?**  
A: After significant milestones or session completions. Use timestamp-based naming.

**Q: Can I create new subfolders in Document/?**  
A: Only if approved and necessary. The current 7 categories should cover most cases.

**Q: What if a file relates to multiple categories?**  
A: Save in the primary category and cross-reference. Create a summary document if it ties together multiple areas.
